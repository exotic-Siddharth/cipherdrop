# Code review, 2026-11-11

Review of CipherDrop at baseline commit `ec0091c` (integration I1 and I2: typecheck, lint, unit, S3 and e2e tests green). The findings were fixed test-first by area fixers (api, web) and integrated and gated in one pass.

## Method

- Lenses: the review ran per area (API and web), each against the spec (`docs/DESIGN.md` with its Decisions log), the build plan's Global Constraints and Review Focus 1-5, and the lane notes. The harness did not pass the individual lens names to the integration step, so they are not listed here. Findings fall into security and abuse resistance, concurrency and data integrity, operations and configuration, accessibility, UI claims, and test quality.
- Triage: raw findings were merged where they described the same defect, one was rejected at triage, and each remaining finding was verified (reproduced or refuted) before a fix was written.
- Rule for fixes: a failing regression test first; a fix without a test that failed before it is not accepted.

## Integration notes

- C-23 introduced an e2e regression: the new live-region text duplicated the success and error headings, so Playwright strict-mode locators matched two elements (17 then 2 failures). The announcements now read "Upload finished. The share link is below." and "Upload failed. Details and a retry button are below."; the unit test was updated.
- A migration `20261111120000_retention_scan_indexes` adds indexes for the new retention scans (Session `expiresAt` and `revokedAt`, RefreshToken `expiresAt`, Report `status, resolvedAt`, AuditEvent `createdAt`).
- `docs/DESIGN.md` gained the new env vars, the rate-limit and cleanup changes and Decisions-log entries.

## Open points

- C-19 server side: rejecting a re-PUT of an existing chunk with a different SHA-256 was not added. The spec and an existing test define re-PUT as an overwrite, and the server cannot stop a malicious client from reusing its own nonces. The client-side tie check covers the honest-client case.
- C-01 trade-off: an attacker who exhausts the per-drop failure budget also blocks recipients until the window ends.
- C-06: blob deletion of an expired drop is delayed by at most the grant lifetime (about 24 h).
- C-15: the in-flight chunk cap is per process; multiple instances need reverse-proxy connection limits.
