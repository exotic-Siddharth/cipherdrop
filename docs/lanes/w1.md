## Decisions

- 2026-11-08: kdf.worker has composite operations (unlockVault, changePassword, rotateRecoveryKey, completeRecovery) so the raw account key never leaves the worker: it is unwrapped, used and zeroed there, and only a non-extractable CryptoKey (R7) or wrapped material is returned. Errors cross as {code, message} (crypto codes plus TYPE_ERROR/RANGE_ERROR) and kdfClient maps them back to the crypto error classes.
- 2026-11-08: The wrong-password path on /unlock, password change and recovery-key rotation is decided locally (unwrap fails with WrongPasswordError) before any request is sent. /unlock loads GET /auth/vault on mount; submitting a password makes no network call.
- 2026-11-08: After login the vault is unlocked with the encKey derived during login (no second Argon2id run): GET /auth/vault then a local unwrap. If that fails the vault stays locked and the dashboard redirects to /unlock.
- 2026-11-08: Register and recover enforce a minimum password: 10 characters and zxcvbn score >= 2 (fallback 12 characters when the lazy estimator is unavailable), checked on submit rather than by disabling the button.
- 2026-11-08: Registration signs the user in immediately (session and vault key set) and shows the recovery-key step; Continue stays disabled until "I saved my recovery key" is checked, and a beforeunload warning guards the unsaved key. Recovery also rotates the recovery key and shows the new one on the same card.
- 2026-11-08: Recovery is two steps: POST /auth/recovery/start (email + recoveryAuthKey), then a new password (plus the 2FA code field only when the server says mfaRequired) and POST /auth/recovery/complete.
- 2026-11-08: Settings adds a Profile card (email, member since, storage meter) and an Appearance card (light/dark/system) to the Account tab, beyond the spec text. Settings tabs have no icons (they overflowed at 390 px).
- 2026-11-08: /how-it-works shows three SVG diagrams (key in the fragment, chunked STREAM encryption, account key hierarchy), the two-column "server stores / never sees" table (stacked lists below 640 px, hidden from assistive tech to avoid duplication) and the honest-limitations list. The plan's "4 diagrams" are delivered as 3 diagrams plus the table.
- 2026-11-08: Login failures are one generic message ("Incorrect email or password. Repeated failures temporarily lock the account."): the server's lockout is also a generic 401, so nothing distinguishes it. 429 uses the shared "try again in N min" text from Retry-After.
