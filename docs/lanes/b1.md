## Integration needs

- apps/api/src/lib/argon2.ts (S4-owned) verifyAuthKey is broken for real authKeys: @node-rs/argon2 2.2 verify() decodes the password as UTF-8 and throws "invalid utf-8 sequence" for binary 32-byte input, so verifyAuthKey returns false for almost every real authKey. B1 works around it with modules/auth/authKeyHash.ts (verifyAccountAuthKey / verifyAccountAuthKeyOrDummy: recompute the tag with hashRaw on raw bytes, constant-time compare; hashes stay compatible with hashAuthKey). Any other consumer that verifies an authKey or recoveryAuthKey (seed, scripts/smoke.ts, admin, drops) must use authKeyHash.ts, or lib/argon2.ts should be fixed to delegate to it.
- test/factories.ts TEST_ACCOUNT is not derivable from its password (fixed bytes). B1 tests derive realistic values via modules/auth/testkit.ts (createAccountBundle with KDF_MIN). Seed and e2e that need a loginable demo user must create it with @cipherdrop/crypto (createAccountBundle + createRecoveryBundle) and hashAuthKey, not TEST_ACCOUNT.
- DELETE /me calls ctx.storage.deleteDrop(dropId) for each owned drop (B2 storage drivers must implement it; B1 tests spy on it). A storage failure aborts the deletion (retryable) before the user row is deleted.
- Web client contract: refresh cookie cd_rt (Path /api/auth, httpOnly, SameSite=Strict); any 4xx except 429 from /auth/refresh means the session is over; access tokens carry iat/exp; POST /auth/recovery/rotate takes {authKey, code (when TOTP is enabled), wrappedAccountKeyRecovery, recoveryAuthHash} and keeps sessions.
- The prelogin, login, loginMfa, register and recovery limiters go through ctx.rateLimit and are only active when RATE_LIMITS_ENABLED=true (off in tests/e2e by default).

## Decisions

- 2026-11-08: authKeys and recoveryAuthKeys are verified with modules/auth/authKeyHash.ts (hashRaw on raw bytes, constant-time compare) instead of lib/argon2 verifyAuthKey, because @node-rs/argon2 verify() rejects non-UTF-8 passwords. Stored PHC hashes are unchanged.
- 2026-11-08: Wrong MFA codes (TOTP or backup) count toward the same 10-failure, 15-minute account lockout as wrong authKeys.
- 2026-11-08: POST /auth/recovery/rotate (R9) is audited RECOVERY_KEY_ROTATED, revokes no sessions, requires the current authKey and, when TOTP is enabled, a TOTP or backup code.
- 2026-11-08: DELETE /me requires the authKey (and a TOTP code when enabled), deletes the blobs of every owned drop first, then the user row; all sessions die at once through the sid denylist.
- 2026-11-08: In tests the next TOTP code is generated with the timestamp set to now + 30000 ms instead of sleeping (R23).
