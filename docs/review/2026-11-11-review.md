# Code review, 2026-11-11

Review of CipherDrop at baseline commit `ec0091c` (integration I1 and I2: typecheck, lint, unit, S3 and e2e tests green). The findings were fixed test-first by area fixers (api, web) and integrated and gated in one pass.

## Method

- Lenses: finder lenses were crypto (cryptography), authapi (zero-knowledge accounts, sessions and API security), drops (drop lifecycle and storage), frontend (frontend security, UX and accessibility), ops (reliability, operations and data hygiene) and spec (spec conformance and test quality). Each ran against the spec (`docs/DESIGN.md` with its Decisions log), the build plan's Global Constraints and Review Focus 1-5, and the lane notes. Verification lenses were reality, intent and impact: critical and high findings got all three (majority wins); medium findings got reality and intent, with impact breaking a tie; low findings were verified in batched reality-and-intent votes. The fixes were then reviewed by two Opus reviewers (back end and web; see round 2). Findings fall into security and abuse resistance, concurrency and data integrity, operations and configuration, accessibility, UI claims, and test quality.
- Triage: raw findings were merged where they described the same defect, one was rejected at triage, and each remaining finding was verified (reproduced or refuted) before a fix was written.
- Rule for fixes: a failing regression test first; a fix without a test that failed before it is not accepted.

## Open points

- C-19 server side: rejecting a re-PUT of an existing chunk with a different SHA-256 was not added. The spec and an existing test define re-PUT as an overwrite, and the server cannot stop a malicious client from reusing its own nonces. The client-side tie check covers the honest-client case.
- C-01 trade-off: an attacker who exhausts the per-drop failure budget also blocks recipients until the window ends.
- C-06: blob deletion of an expired drop is delayed by at most the grant lifetime (about 24 h).
- C-15 and C-09: the in-flight caps (uploads and downloads) are per process; multiple instances need reverse-proxy connection limits. The per-IP caps use `req.ip`, so behind a proxy they are only as good as `TRUST_PROXY`.
- C-R2-05: reports are accepted for EXPIRED drops until their blobs are purged, but the admin review grant (`reviewGrant` in `modules/admin/service.ts`) still answers 410 for EXPIRED drops, so a report on an expired drop can be recorded before an admin can open the content. Whether review should also allow unpurged EXPIRED drops is left open.
- C-R2-01: a crash between the blob write and the commit leaves an unreferenced blob version; it is removed with the rest of the drop prefix when the drop is purged, there is no earlier sweep. A write refused after the purge now deletes the whole drop prefix with retries. A crash between that write and the delete, or a storage error that outlasts all three `deleteDrop` attempts, leaves the blob, and there is no storage sweep. This covers any already-purged drop (`blobsDeletedAt` set, EXPIRED and EXHAUSTED included), not only missing, DELETED or DISABLED drops (C-R4-01).
- C-R3-01: the slowest uplink an honest client can use is set by Node's 300 s `requestTimeout` per 4 MiB chunk: about 14 KB/s per PUT, about 0.34 Mbit/s for the 3-lane web uploader.
- C-R3-03: the per-IP in-flight shares are keyed per IPv4 address or IPv6 /48. Clients behind one IPv4 NAT or one /48 still share them.
- Sign out during an upload (C-R2-12, C-R3-07, C-R3-09) is covered by unit tests only; the e2e suite does not sign out mid-upload.
- Resume record (C-R4-02, C-R4-04): a record written before round 4 lacks the option fields and is dropped as invalid on read, so such a drop is not resumable after the upgrade. After a reload the page cannot vouch for the note or password of the old drop, so a form with a note or password gives up the resume and starts a new drop; this is deliberate, the secrets are never stored.
- Round 4 is the final pass and was not fix-reviewed again; its check is the full gate. The unit tests cover the resume-flow changes; the e2e resume spec (anonymous, default options, reload) is the only browser-level check of them.
- Deferred to polish: `docs/SECURITY.md`, a fresh upload-throughput measurement on `vite preview`, and removal of the `docs/review/fx-*.md` and `integrate.md` working notes.
